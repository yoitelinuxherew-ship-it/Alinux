The Koax Anime API uses cursor-free, page-based pagination for all list endpoints. Because collections like anime or manga can contain tens of thousands of entries, every list response returns a bounded slice of results alongside a `pagination` metadata object that tells you exactly where you are in the full dataset. You control the slice using two simple query parameters — `page` and `limit` — or use `offset` if you prefer index-based navigation.

## Query Parameters

<ParamField query="page" type="integer" default="1">
  The page number to retrieve. Page numbering starts at `1`. Requesting a page beyond `total_pages` returns an empty `data` array with `has_next: false`.
</ParamField>

<ParamField query="limit" type="integer" default="25">
  Number of results to include per page. Must be between `1` and `50`. Values above `50` are rejected with a `422 VALIDATION_ERROR`.
</ParamField>

<ParamField query="offset" type="integer">
  Alternative to `page` — the zero-based index of the first result you want. For example, `offset=50` with `limit=25` returns results 51–75. If you supply both `page` and `offset`, `offset` takes precedence.
</ParamField>

## Pagination Response

Every list endpoint wraps its results in a consistent envelope. The `data` array contains the requested resource objects, while the `pagination` object gives you all the metadata you need to build navigation controls or drive a loop.

```json
{
  "data": [...],
  "pagination": {
    "total": 2847,
    "page": 1,
    "limit": 25,
    "has_next": true,
    "has_prev": false,
    "total_pages": 114
  }
}
```

| Field | Type | Description |
|---|---|---|
| `total` | integer | Total number of records matching your query across all pages. |
| `page` | integer | The current page number. |
| `limit` | integer | Number of results per page as applied to this response. |
| `has_next` | boolean | `true` if there is a subsequent page to fetch. |
| `has_prev` | boolean | `true` if you are past the first page. |
| `total_pages` | integer | Total number of pages at the current `limit`. |

## Example: Fetching Page 2

The example below fetches the second page of anime results, requesting 25 items per page. Check `has_next` in the response to decide whether to fetch more pages.

<CodeGroup>

```bash curl
curl "https://api.koax.dev/v1/anime?page=2&limit=25" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript JavaScript
const response = await fetch(
  "https://api.koax.dev/v1/anime?page=2&limit=25",
  {
    headers: {
      Authorization: "Bearer YOUR_API_KEY",
    },
  }
);

const { data, pagination } = await response.json();

console.log(`Page ${pagination.page} of ${pagination.total_pages}`);
console.log(`Showing ${data.length} of ${pagination.total} results`);

if (pagination.has_next) {
  console.log("More pages available — increment page to continue.");
}
```

</CodeGroup>

### Iterating Through All Pages

If you need to collect all results, loop until `has_next` is `false`:

<CodeGroup>

```javascript JavaScript
async function fetchAllAnime() {
  const results = [];
  let page = 1;
  let hasNext = true;

  while (hasNext) {
    const response = await fetch(
      `https://api.koax.dev/v1/anime?page=${page}&limit=50`,
      { headers: { Authorization: "Bearer YOUR_API_KEY" } }
    );
    const { data, pagination } = await response.json();

    results.push(...data);
    hasNext = pagination.has_next;
    page += 1;
  }

  return results;
}
```

```python Python
import requests

def fetch_all_anime(api_key):
    results = []
    page = 1
    has_next = True

    while has_next:
        response = requests.get(
            "https://api.koax.dev/v1/anime",
            params={"page": page, "limit": 50},
            headers={"Authorization": f"Bearer {api_key}"},
        )
        body = response.json()
        results.extend(body["data"])
        has_next = body["pagination"]["has_next"]
        page += 1

    return results
```

</CodeGroup>

<Tip>
  Set `limit=50` whenever you need to scan a large collection. Halving the number of requests cuts both your latency and rate-limit consumption — especially important on the Free plan where you have a tighter daily quota.
</Tip>

<Note>
  The maximum allowed value for `limit` is **50 results per request**. Requests with a higher value return a `422 VALIDATION_ERROR`. If your use case requires bulk data export, consider combining `limit=50` pagination with local caching rather than repeatedly hitting the API.
</Note>
