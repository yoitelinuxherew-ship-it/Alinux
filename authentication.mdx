Every request you send to the Koax Anime API must include a valid API key. Authentication uses the standard HTTP `Authorization` header with the `Bearer` scheme — a widely adopted pattern that works seamlessly with any HTTP client, framework, or language. Without a valid key, the API returns a `401 Unauthorized` error and the request is not processed.

## Get Your API Key

<Steps>
  <Step title="Create a free account">
    Visit [https://koax.dev/signup](https://koax.dev/signup) and complete the sign-up form. Check your inbox for a verification email and click the confirmation link.
  </Step>
  <Step title="Open the API Keys page">
    After logging in, navigate to **Dashboard → API Keys** from the top navigation bar.
  </Step>
  <Step title="Generate a new key">
    Click **Generate New Key**. Give it a meaningful label — for example, `production-app` or `local-dev` — so you can identify it later. Then click **Create**.
  </Step>
  <Step title="Copy and store your key securely">
    Your full key is displayed **only once**. Copy it immediately and save it in a secure location such as a password manager or a secrets vault. After you close the dialog, only the last four characters are shown for identification.
  </Step>
</Steps>

## Make Authenticated Requests

Include your API key in the `Authorization` header of every HTTP request using the `Bearer` token format:

```
Authorization: Bearer YOUR_API_KEY
```

Here is a complete example using `curl`:

```bash
curl -H "Authorization: Bearer YOUR_API_KEY" \
  https://api.koax.dev/v1/anime/top
```

The header must be present on every request — the API does not use cookies, query-string parameters, or session tokens for authentication.

### Code Examples

<CodeGroup>

```bash curl
curl -H "Authorization: Bearer YOUR_API_KEY" \
  "https://api.koax.dev/v1/anime/search?q=naruto&genre=action"
```

```javascript JavaScript
const response = await fetch(
  "https://api.koax.dev/v1/anime/search?q=naruto&genre=action",
  {
    headers: {
      Authorization: "Bearer YOUR_API_KEY",
    },
  }
);

const data = await response.json();
console.log(data);
```

```python Python
import requests

response = requests.get(
    "https://api.koax.dev/v1/anime/search",
    params={"q": "naruto", "genre": "action"},
    headers={"Authorization": "Bearer YOUR_API_KEY"},
)

data = response.json()
print(data)
```

</CodeGroup>

## API Key Security

<Warning>
  **Never expose your API key in client-side code.** Embedding a key in a public JavaScript bundle, a mobile app binary, or a public GitHub repository gives anyone who finds it full access to your account and quota. Always keep keys server-side.
</Warning>

Follow these practices to keep your key safe:

- **Use environment variables.** Store your key in an environment variable (e.g. `KOAX_API_KEY`) and read it at runtime rather than hard-coding it in source files.
- **Keep keys out of version control.** Add `.env` files to your `.gitignore` before you ever commit them.
- **Rotate keys regularly.** Generate a new key on a schedule (or immediately after any suspected exposure) and revoke the old one from the Dashboard.
- **Use separate keys per environment.** Create distinct keys for development, staging, and production so you can revoke one without affecting the others.
- **Restrict key scope where possible.** Future Dashboard updates will let you limit a key to specific endpoints or IP ranges — take advantage of these controls when they are available.

## Authentication Errors

If something goes wrong with authentication, the API responds with one of the following HTTP status codes:

| Status Code | Name | Cause |
|---|---|---|
| `401 Unauthorized` | Missing or invalid API key | The `Authorization` header is absent, malformed, or contains an unrecognized key. Check that you included `Bearer ` (with a space) before your key. |
| `403 Forbidden` | Insufficient permissions | Your key is valid but does not have access to the requested resource. This can happen if the endpoint requires a paid plan. |
| `429 Too Many Requests` | Rate limit exceeded | You have sent more requests than your plan allows within the current window. Wait until the window resets or upgrade your plan. |

All error responses follow the same JSON shape:

```json
{
  "status": "error",
  "code": 401,
  "message": "Invalid or missing API key. Include your key in the Authorization header as: Bearer YOUR_API_KEY"
}
```

<Note>
  The free tier allows **1,000 requests per day**. Once you reach this limit, all further requests return `429 Too Many Requests` until the counter resets at midnight UTC. For higher limits, see the [rate limits page](/concepts/rate-limits) or visit [koax.dev/pricing](https://koax.dev/pricing) to explore paid plans.
</Note>
